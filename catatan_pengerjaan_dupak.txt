A. Controller: app/Http/Controllers/Dupak/DashboardController.php
   Temuan:
   1. Import `use Illuminate\Container\Attributes\DB;` ADA namun TIDAK PERNAH DIGUNAKAN. Seharusnya dihapus atau diganti dengan `Illuminate\Support\Facades\DB` jika dibutuhkan.
   2. Property `$aturanPengajuanJFA` berisi hardcoded UUID map yang DIDUPLIKASI juga di `PengajuanController`. Perlu di-refactor ke config atau helper agar Single Source of Truth.
   3. Method `getCurrentJFA()` menggunakan `latest()->first()` tanpa memeriksa `tmt_selesai IS NULL`. Ini berpotensi mengambil riwayat JFA yang sudah tidak aktif. HARUS ditambahkan `whereNull('tmt_selesai')` agar sesuai dengan logika JFA aktif.
   4. Method `getTargetKum()` mengakses `$refJfa?->minimal_kum`, namun field `minimal_kum` TIDAK ADA di tabel/model `refJabatanFungsionalAkademik`. Akibatnya fallback selalu ke 0.
   5. Method `hasPendingSubmission()` menggunakan array status: `['draft', 'submitted', 'reviewed', 'pending']`. Status aktual di database saat create/store adalah 'Pending' (kapital), dan di view badge menggunakan: Draft, Diajukan, Menunggu, Ditolak, Diterima, Revisi. Terdapat KETIDAKSAMAAN CASE dan nama status, sehingga logika pending bisa gagal mendeteksi.
   6. Method `submissions()` menggunakan fallback string `'___INVALID___'` untuk non-admin tanpa dosenId. Cara ini berfungsi tapi kurang elegan.
   7. Comment debug `// dd($jfaAsal, $riwayat);` dan serupa lainnya masih tertinggal di kode produksi (lines 77, 170, 173, 176).

   Status: BUTUH PERBAIKAN
